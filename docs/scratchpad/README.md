# Scratchpad

Working material: grilling prompts, session notes, drafts on their way to becoming a spec, a
ticket or an ADR.

Nothing here is a contract. `docs/adr/` records decisions, `docs/frontend/` records the blueprint,
`docs/specs/` records what a ticket asked for — those are authoritative and this is not. A file
here is a snapshot of thinking at a moment, and it goes stale the day after it is written.

Two rules that keep it useful rather than archaeological:

- **Name the file for its subject, not its date** — `grilling-form-engine-parity.md`, not
  `2026-08-07-notes.md`.
- **When a scratchpad file has done its job, delete it or promote it.** If its conclusion matters,
  it belongs in an ADR or a spec; if it does not, it belongs in the bin. Leaving it here is how a
  superseded position gets cited back as though it were settled.
